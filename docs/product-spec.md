# SupportOps 产品规格 v0.1

日期：2026-10-04。目标：本地运行、GitHub 展示的大模型应用工程项目。

## 用户、产品和任务

面向技术支持工程师，调查自建产品 RelayDesk 的工单。RelayDesk 是限定规模的事件投递软件，第 2 阶段第 3 轮已使用独立 Docker API、PostgreSQL、Redis 与下游接收器实现本地实验。版本固定为 1.0、1.1、2.0；配置不匹配、连接池超时、缓存旧值与下游超时共 24 次三阶段实验已真实运行，支持观测回查。故障标签只进入实验控制与评测侧。运行核对与未测条款见该轮验收；本地实验不代表生产性能或 SLA。

主流程：工单入库 → 环境与版本澄清 → 文档 / 案例检索 → 日志 / 环境取证 → 假设验证 → 带证据的建议 → 人工批准限定动作 → 执行与固定复测 → 复盘与候选经验。简单问题保留直接问答路线。

## 深度与边界

- 检索保留向量基线、BM25、RRF、rerank、结构切片和父块扩展的独立实验。
- 结论分别检查引用身份、原文字面和语义支持；历史案例不能证明当前根因。
- Agent 规划与工具执行分层，代码拥有权限、参数、预算、状态转换与副作用幂等。
- Skill 有版本、适用范围、原始来源与回归门槛；记忆支持撤销、失效和冲突处理。
- 两个调查子 Agent 与单 Agent 做同任务、同模型、同总预算比较。
- 只运行本地实验动作；无公网部署、任意 SQL / Shell、模型训练或自动修改应用源码。
- 四个工作区：工单调查、知识与案例、经验与 Skill、评测与运行轨迹。
- 数据来源区分构造案例、用户报告、实际工具观测；来源标记本身不能证明真实性。

## 工程与模型计划

Python 3.12 / FastAPI / Pydantic，后续引入 PostgreSQL / pgvector、SQLAlchemy / Alembic、LangGraph、独立 Worker、项目 Skill Loader、MCP、Vue 3 / TypeScript / Vite / Element Plus、OpenTelemetry、Docker Compose。采用模块化单体，业务数据库与实验产品数据库独立。每轮只安装实际所需依赖并固定版本。

沿用提案中的百炼质量基线：主模型、embedding、rerank 与轻任务模型分别显式配置。qwen3.8-max-0902、qwen3.7-text-embedding、qwen3.7-text-rerank、qwen3.8-flash 已在第 1 阶段第 3 轮完成本机账号的最小真实接口验证；这不代表后续检索或回答质量。本轮没有模型调用；失败明确停止，不切换其它模型或后端。

## 评测与交付

先建立 20～30 个高质量标注案例，逐步扩展至约 120 个检索 / 回答案例和 24～36 个调查任务。开发集与保留集按来源、模板、版本和故障家族分组，答案不进入 Agent 上下文。指标、所有运行分母、失败样本、模型参数、知识快照、token、时延与费用随运行保存。没有实验结果时不填写成功率。

用户逐轮验收后继续；总计 24 轮，轮次是交付范围。当前状态只以 implementation-plan.md 和每轮 acceptance.md 为准。公开内容只包括允许分发的数据、规格、源码、测试、实际结果和历史 trace；上传时单独核对密钥与数据。
