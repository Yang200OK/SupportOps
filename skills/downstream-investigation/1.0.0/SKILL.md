# 下游超时排查

适用 RelayDesk 1.0 / 1.1 / 2.0 的在线实验。RD_TIMEOUT 只能引导核对响应链路。

1. 检索同版本投递超时配置与单位，不能套用其它版本的键。
2. 读取 read_runtime_state，了解有效超时与接收器设置；配置延迟不是本次实际等待。
3. 读取 read_current_observations，比较本次固定请求的产品与接收器事件，确认请求是否到达、实际等待与结果。
4. 超时错误码不等于下游慢根因；连接池等待、缓存目标等候选需要各自本次证据。没有日志不能排除其它原因。
5. 只给有依据的检查或未决候选。任何改变超时的实验动作必须独立人工批准，动作后固定复测，不能宣称生产 SLA。

这是自建设计资料的手工方法，尚未人工语义审定或评测收益。方法不授予权限，不调整预算，不作为事实引用。
