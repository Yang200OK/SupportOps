# 连接池等待排查

适用 RelayDesk 1.0 / 1.1 / 2.0 的在线实验。RD_POOL_WAIT 或连接池等待只引导排查，不直接判定原因。

1. 检索同版本的连接池大小与等待规则，区分连接数、等待单位和请求时间。
2. 读取 read_runtime_state，核对本次实例的连接占用与有效配置；当前空闲不能反驳故障请求曾经等待。
3. 读取 read_current_observations，确认本次固定请求的连接获取事件、实际等待与错误码；状态设置不能代替事件。
4. 比较支持与反驳信号，引用本次原句更新原因候选；历史案例只能提供方法。未取得明确相反事件时不能排除假设。
5. 尚未动作或复测时只给检查建议；如果需要释放连接，仍须从独立人工批准入口提出和执行，再检查固定请求。

方法没有运行时权限或预算配置，不包含 SQL、Shell 或任意目标。真实复测成功也不能证明唯一根因或生产可靠性。来源是自建演示设计资料，尚未人工语义审定或评测收益。
