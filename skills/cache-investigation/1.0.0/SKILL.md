# 缓存目标与代次排查

适用 RelayDesk 1.0 / 1.1 / 2.0 的在线实验。RD_CACHE_STALE 与缓存旧值是排查线索。

1. 检索同版本缓存与时间单位规则；文档默认值不证明当前 TTL。
2. 读取 read_runtime_state，比较数据库目标、缓存目标与代次。
3. 读取 read_current_observations，核对本次固定请求实际使用的目标与事件，不能用历史实验代替本次取证。
4. 目标或代次不一致不能推成 TTL 到期、后台刷新失败；没有这类事件就保留信息缺口。
5. 只引用本次记录更新候选，冲突保持未决。清缓存需要独立人工批准，之后固定复测；方法文本本身不是批准或现场证据。

这是自建演示资料的手工排查方法，未人工语义审定或比较有无方法的效果。工具白名单、预算、实例身份、参数及动作授权由应用代码决定。
